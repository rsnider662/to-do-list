# to-do-list

## Пользователь
Пользователем может быть любой человек, которому нужно планировать свои дела.
Проект решает проблему планирования и решения задач в срок. С приложением to-do list планирование становится куда проще, что позволяет грамотно распределять свое время.

## Основная сущность
Сущность: task - задача.
Поля:
id – идентификатор (str)
title – название задачи (str)
description – описание задачи (str многостраничный)
status – статус задачи
priority – приоритет по важности (num)
dueDate – срок выполнения (str)
isActive – активна/завершена (bul)

## Страницы
Страницы и их назначения:
Dashboard – общее количество задач, активные, выполненные, по приоритету. Блок задач, требующий внимания.
Список задач — список задач с поиском по названию, фильтрацией и сортировкой.
Карточка задачи — описание задачи, изменение статуса, редактирование, удаление.
Создание задачи — форма с полями: название, описание, статус, приоритет, срок выполнения.
Редактирование задачи — та же форма с заполненными данными для замены.
Статистика — расширенная аналитика: динамика выполнения и тд.

## Сценарии
Сценарий 1: Добавление новой задачи.
1. Пользователь нажимает кнопку «Создать новую запись» на dashboard.
2. Далее он видит форму для заполнения новой задачи.
3. Нажимает кнопку «Сохранить».
4. Задача появляется странице со списком задач.

Сценарий 2: Просмотр созданной задачи
1. Пользователь нажимает кнопку «Просмотр задач» на dashboard.
2. Пользователь видит созданный им список задач.
3. Пользователь видит нужную ему задачу и нажимает на нее.
4. Перед пользователем открывается карточка задачи.

Сценарий 3: Редактирование задачи
1. Пользователь нажимает кнопку «Просмотр задач» на dashboard.
2. Пользователь видит созданный им список задач.
3. Пользователь видит нужную ему задачу и нажимает на нее.
4. Перед пользователем открывается карточка задачи.
5. Пользователь нажимает кнопку «Редактировать задачу».
6. Перед пользователем открывается форма с данными задачи, которые можно переписать.
7. Пользователь нажимает кнопку «Сохранить».
8. Задача обновляется на странице со списком задач.

Сценарий 4: Удаление задачи
1. Пользователь нажимает кнопку «Просмотр задач» на dashboard.
2. Пользователь видит созданный им список задач.
3. Пользователь видит нужную ему задачу и нажимает на нее.
4. Перед пользователем открывается карточка задачи.
5. Пользователь нажимает кнопку «Удалить задачу».
6. Задача удаляется, пользователя перебрасывает на страницу со списком задач.

Сценарий 5: Поиск задачи
1. Пользователь нажимает кнопку «Просмотр задач» на dashboard.
2. Пользователь видит поисковое поле в верхней части страницы.
3. Пользователь вводит название задачи.
4. Перед пользователем остается только задачи с названием, которое указал пользователь.
5. Пользователь нажимает на задачу и переходит к карточке задачи.
